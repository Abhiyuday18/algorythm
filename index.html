How AlgoRythm works

What is this?

AlgoRythm is a teaching tool for classic computer science algorithms. Every visualization can be played automatically or advanced one operation at a time, with the executing pseudocode line highlighted and a plain-English explanation of each step. The whole app is a single HTML file with zero dependencies: it runs offline, from a USB stick, or on locked-down lab machines with nothing to install.

The six visualizers

  • Sorting: Bubble, Selection, Insertion, Merge, and Quick Sort as animated bar charts, with comparison and swap counters.
  • Binary Search: watch the search space halve on every step, with low/high/mid markers.
  • Pathfinder: draw walls, move the start and end, then run BFS, DFS, or Dijkstra. Dijkstra runs on a weighted grid where every cell has a visible 1-9 cost and finds the true lowest-cost path.
  • Towers of Hanoi: the recursive solution played move by move.
  • N-Queens and Sudoku: backtracking, including the failed attempts most visualizers skip.

The four sorting modes

  • Single: one algorithm, with Run (auto-play) and Step (one operation per click).
  • Compare: two algorithms race on identical copies of the same array, ending with a summary of who finished first and a plain-English explanation of why.
  • Benchmark: all five algorithms are measured on real arrays at doubling sizes (8 to 256) and the operation counts are plotted, so the O(n²) vs O(n log n) gap appears as data. Choose the input pattern (random, nearly sorted, reversed, few unique values) to see the rankings change.
  • Challenge: the animation pauses mid-run and asks you to predict the next operation before it happens, with score and streak tracking. Every question is answerable from what is on screen.

Keyboard controls

  • Tab reaches every card, control, and button; Enter or Space activates.
  • In the Pathfinder, focus the grid and use arrow keys to move the cursor, then Enter or Space to draw a wall or place the start/end (depending on the selected mode). A screen-reader live region announces the cursor position and cell state.
  • A hidden easter egg is typed, not clicked.

Under the hood

Every algorithm is written once as a JavaScript generator function that yields at each visual step. The Run button drains that generator on a timer; the Step button advances it one .next() per click; Compare Mode advances two generators in lockstep; Benchmark Mode drains them silently to count operations; Challenge Mode reads the structured log they emit to build quiz questions. One implementation, five consumers, so the animation, the measurements, and the quiz can never disagree with each other.

The project ships with a 74-test suite that loads this exact file into a simulated browser and checks every algorithm against independent reference implementations on every push. See ARCHITECTURE.md in the repository for the full write-up.

Pseudocode
function binarySearch(arr, target):
  low = 0, high = len - 1
  while low <= high:
    mid = (low + high) / 2
    if arr[mid] == target: return mid
    if arr[mid] < target: low = mid + 1
    else: high = mid - 1
  return -1 // not found

Pseudocode
solve(board, row):
  if row == N: return true
  for col in 0..N:
    if isSafe(board, row, col):
      board[row] = col
      if solve(row + 1): return true
      board[row] = -1 // backtrack
  return false

solve(board):
  cell = findEmpty(board)
  if no empty cell: return true
  for num in 1..9:
    if isValid(board, cell, num):
      board[cell] = num
      if solve(board): return true
      board[cell] = 0 // backtrack
  return false
